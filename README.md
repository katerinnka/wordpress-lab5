В ходе работы были выполнены:
- настройка пользователей и ролей;
- обновление системы;
- базовое hardening WordPress;

## Шаг 4. Базовое hardening

Отключено редактирование файлов через админ-панель с помощью настройки:

define('DISALLOW_FILE_EDIT', true);

Установлены корректные права доступа:
папки — 755;
файлы — 644.

В файл .htaccess добавлена защита wp-config.php:

<files wp-config.php> order allow,deny deny from all </files>

Данные меры повышают безопасность и защищают конфигурационные файлы.

Установлен и активирован плагин безопасности All In One WP Security & Firewall.

максимум 5 попыток входа;

проверено отсутствие пользователя admin.

включён базовый firewall;

## Ответы на контрольные вопросы
Почему DISALLOW_FILE_EDIT важен?

Данная настройка отключает возможность редактирования файлов через админ-панель WordPress. Это предотвращает изменение кода злоумышленником в случае получения доступа к админке.
Также защита файла wp-config.php предотвращает утечку данных базы данных.

Почему выбраны такие настройки Login Lockdown?

Ограничение в 5 попыток входа позволяет предотвратить brute-force атаки.
Интервал в 15 минут и блокировка на 30 минут обеспечивают баланс между безопасностью и удобством пользователей.

Чем отличается защита WordPress от серверной?

Защита WordPress (через плагины) работает на уровне приложения:
контроль пользователей;
фильтрация запросов;
защита входа.

Серверная защита работает на более низком уровне:
firewall;
права доступа;
защита файловой системы.

Что входит в полный бэкап?

Полный бэкап включает:
базу данных (посты, пользователи, настройки);
файлы сайта (темы, плагины, изображения).

Проверка выполняется путём восстановления данных и проверки их целостности.
